# 图片粘贴与附件（media-001）设计

日期：2026-11-14 · 状态：已批准（2026-11-14，第九节全部按推荐），已实现（2026-11-14）

## 一、要解决什么

现在笔记里只能写文字。截图、手机拍的板书、论文里的图，都没法放进笔记：

- 粘贴截图：什么都不发生（剪贴板里的图片被丢掉）。
- 手写 `![](某张图.png)`：预览里是一张裂开的图，因为服务端不提供笔记目录里的文件。

目标是：**截图后在正文里 Ctrl+V，图片就进了笔记**，预览、阅览模式、导出的 PDF 里都能看到，备份时也一起备份。

## 二、现状（和这个功能有关的部分）

| 地方 | 现在的情况 | 对本功能的影响 |
|---|---|---|
| 写接口闸门（`server/app.ts`） | 有请求体的写接口只收 `application/json`（AGENTS.md 约束 4，不能放宽） | 上传不能用 multipart，只能把图片转成 base64 放进 JSON |
| 请求体上限（`server/api.ts`） | 5MB | base64 会放大约 1/3，原图只能到约 3.7MB，手机照片常常超 |
| 静态文件 | 只提供前端构建产物 `dist/`，不提供 `data/notes` 里的文件 | 预览里的图片需要一个读文件的接口 |
| Markdown 渲染（`web/src/lib/markdown.ts`） | 图片用 marked 默认渲染，`src` 原样输出；`![[图片]]` 原样保留不解析 | 需要把相对路径换成读文件接口的地址；支持 `![[ ]]` |
| 备份（`server/backup.ts`） | 只扫描 `.md` 文件 | 不改的话，图片不会进 WebDAV 备份，换电脑就丢 |
| 导出 PDF（`server/export.ts`） | 内容安全策略只允许 `data:` 和网络图片 | 本地图片要在导出时直接嵌进 HTML |
| 索引 / 外部编辑同步 | 只看 `.md` | 图片文件不会被误当成笔记，不需要改 |
| git | `data/notes/*` 已被忽略 | 附件跟着笔记一起不进 git，不需要改 |

## 三、目标

1. 在正文框里**粘贴**或**拖入**图片：图片存进笔记库，光标处插入图片语法，预览立刻显示。可以一次放多张。
2. 插入的是**标准 Markdown**，换用 Typora、VS Code、Obsidian 打开 `data/notes` 也能看到图（Markdown 文件是唯一真源，约束 1）。
3. 预览、分栏、阅览模式、导出的 PDF 都显示图片。
4. 别的工具写的 `![[图片.png]]`（Obsidian 写法）也能显示。
5. 图片随笔记一起备份到 WebDAV。
6. 插入后 `Ctrl+Z` 能撤回那段文字（图片文件保留，不影响正文）。

## 四、非目标

- 不做图片编辑（裁剪、标注、旋转）。
- 不自动压缩、不转格式：存的就是你粘贴的原图。
- 不做 PDF、Word 等非图片附件（以后需要再说）。
- 不自动删除「没有笔记再引用」的图片。删笔记时图片留着，避免误删；以后可以加一个「清理没用到的图片」功能。
- 不在历史版本里存图片：图片文件名带内容指纹，写进去就不会再被改，旧版本笔记引用的图一直都在。

## 五、反目标（出现这些就算失败）

- 粘贴的图片只存在 SQLite 或浏览器里，换个编辑器打开 Markdown 看不到。
- 通过读文件接口能读到笔记库以外的文件，或读到 `config.json`（里面有 API Key）。
- 打开一张恶意图片（比如带脚本的 SVG）能在应用里执行脚本。
- 为了上传，放宽了写接口的 Content-Type 闸门。
- 引入新的运行时依赖。

## 六、方案

### 1. 图片存在哪、叫什么名字

- **位置**：笔记库里统一一个文件夹 `data/notes/attachments/`。
  - 不放在每篇笔记旁边：笔记会在 `inbox/` 等目录里，分组只改 frontmatter、不移动文件，统一放一处最简单，也最好找。
- **文件名**：`日期-时间-内容指纹.扩展名`，例如 `20261114-153012-a1b2c3d4.png`。
  - 内容指纹是图片内容 SHA-256 的前 8 位：**同一张图粘贴两次只存一份**（文件已存在就直接复用）。
  - 拖进来的文件如果有自己的名字（如 `板书.jpg`），名字保留在前面：`板书-a1b2c3d4.jpg`，方便你在文件夹里认出来。名字里 Windows 不允许的字符替换掉，长度截到 40 字。
- 写文件用原子写（先写临时文件再改名），和笔记一致。

### 2. 插入什么语法

插入标准 Markdown，路径**相对于当前笔记所在的目录**：

- 笔记在根目录：`![](attachments/20261114-153012-a1b2c3d4.png)`
- 笔记在 `inbox/` 里：`![](../attachments/20261114-153012-a1b2c3d4.png)`

这是 Typora、VS Code、Obsidian（关掉「wiki 链接」时）、大多数手机 Markdown App 都认的写法。方括号里的说明文字留空，你可以自己补。

### 3. 上传接口：`POST /api/attachments`

- 请求体是 JSON：`{ "noteId": "...", "name": "板书.jpg", "dataBase64": "..." }`。
  - 走 JSON 是因为写接口闸门只收 JSON（约束 4），不放宽它。
- 这个接口单独把请求体上限提高到 **20MB**（原图约 15MB）；其他接口仍是 5MB。
- 服务端**按文件头判断真实类型**，只收 PNG、JPEG、GIF、WebP。扩展名按真实类型定，不信前端给的名字或类型。
  - **不收 SVG**：SVG 里可以写脚本。
- 返回 `{ "relPath": "attachments/....png", "markdown": "![](../attachments/....png)", "reused": false }`。前端直接把 `markdown` 插到光标处。
- 错误：类型不支持 → 415；太大 → 413；笔记不存在 → 404。前端都显示成人话提示。

### 4. 读文件接口：`GET /api/files/<笔记库内相对路径>`

- 只读、只限笔记库内，复用 `store.absPath` 的路径越界检查（包括 Windows 目录链接 junction 的检查）。
- **只提供图片**（png / jpg / jpeg / gif / webp / svg），其他扩展名一律 404。所以 `.md`、`config.json`（本来也不在笔记库里）都读不到。
- 安全响应头：`X-Content-Type-Options: nosniff`。SVG 额外加 `Content-Security-Policy: sandbox`，直接在标签页打开也不会执行脚本。
  - SVG 不能上传，但你自己放进去的 SVG 可以显示。
- 缓存：文件名带内容指纹，可以长缓存；手放进去的同名文件用修改时间做 ETag。

### 5. 显示：预览 / 阅览模式

- `renderMarkdown` 增加一个参数：当前笔记的路径。
  - 图片的 `src` 是相对路径时，按笔记所在目录换算成 `/api/files/...`。
  - 换算后跑出笔记库的路径直接不显示（服务端还会再挡一次）。
  - `http(s):` 网络图片和 `data:image/` 保持原样。
  - 其他协议（`javascript:` 等）丢掉。
- `![[图片.png]]`（Obsidian 写法）：先在笔记所在目录找，再到 `attachments/` 里找，按文件名渲染成图片。
  - 写成 `![[图片.png|300]]` 时，`300` 当作宽度。
  - `![[某篇笔记]]`（嵌入笔记）不在本期范围，保持原样显示。
- 样式沿用现有的 `.preview img { max-width: 100% }`。

### 6. 前端：粘贴和拖入

- 正文框的 `paste` 事件里，剪贴板有图片文件 → 阻止默认粘贴，逐张上传。
  - 剪贴板里同时有文字和图片时（例如从网页复制），**以文字为准**，照常粘贴文字。
- 正文框支持把图片文件拖进来；拖动时正文框出现淡色边框提示。
- 上传期间底部提示「正在保存图片…」。完成后在**当时的光标处**用 insertText 插入，可以 `Ctrl+Z` 撤回。多张图之间空一行。
- 失败时用提示条说明原因（例如「只支持 PNG、JPG、GIF、WebP」「图片超过 15MB」），正文不动。
- 插入后照常自动保存（「停手 5 秒」规则）。

### 7. 导出 PDF

`buildExportHtml` 渲染时把笔记库内的图片读出来，转成 `data:` 地址直接嵌进 HTML。

- 现有的内容安全策略本来就允许 `data:` 图片，不需要放宽。
- 读不到的图片显示成「[图片缺失：文件名]」。
- 单篇导出里嵌入的图片总量超过 50MB 时，后面的图片不再嵌入，改用同样的缺失提示，避免生成卡死。

### 8. 备份

`scanNotes` 除了 `.md`，也扫描笔记库里的图片文件（同样跳过隐藏目录），按内容 hash 判断有没有变化。

- 图片文件名带指纹、内容不会再变，所以每张图只在第一次备份时上传一次。
- 对请求额度（坚果云免费版每 30 分钟 600 次）的影响：每张新图多 1 次上传请求。平常一次只会新增几张，影响很小。
- 首次全量备份如果一次有几百张图，仍可能碰到额度上限，这是 backup-001 要解决的问题，本功能不处理。

## 八、验证

- **单元测试**：
  - 文件头识别（伪装成 PNG 的文本被拒）。
  - 文件名清洗（Windows 非法字符、超长、中文名）。
  - 相对路径换算（根目录 / 子目录笔记，`../` 越界被挡）。
  - `![[ ]]` 解析。
  - 剪贴板里文字和图片同时存在时的取舍。
- **接口测试**：
  - 上传后磁盘上有文件、返回的 markdown 正确。
  - 同一张图第二次上传复用原文件。
  - 拒绝 SVG 和假图片；超过上限返回 413。
  - 读文件接口拒绝 `../`、`.md`、junction 越界；SVG 响应带 sandbox 头。
- **备份测试**：图片进入扫描结果，没变化的不重复上传。
- **导出测试**：导出的 HTML 里图片是 `data:`。
- **E2E**：
  - 在正文框里模拟粘贴一张 PNG：插入 `![](attachments/...)`，预览里图片真的加载出来（检查 `naturalWidth > 0`），`Ctrl+Z` 能撤回文字。
  - 子目录笔记插入 `../attachments/...`。
  - 导出 PDF 里有这张图。

## 九、需要你决定的

| # | 问题 | 推荐 | 其他选择 |
|---|---|---|---|
| 1 | 图片放在哪 | 统一放 `data/notes/attachments/` | 每篇笔记一个同名文件夹 |
| 2 | 插入的写法 | 标准 `![](相对路径)`，别的软件都认 | Obsidian 的 `![[文件名]]`，更短，但只有 Obsidian 认（两种都能显示） |
| 3 | 单张大小上限 | 15MB，存原图不压缩 | 大于 2MB 的图自动压缩成 JPEG（省空间、备份快，但画质有损、截图里的文字会糊） |
| 4 | 图片要不要一起备份 | 要 | 不要（只备份文字，图片丢了就丢了） |
| 5 | 文件名 | `日期-时间-指纹.png`，拖入的保留原名在前 | 用笔记标题开头，如 `梯度下降-1.png`（好认，但改标题后对不上） |

## 十、实现顺序

1. 后端：`attachments.ts` + 两个接口 + 测试。
2. 渲染：路径换算、`![[ ]]` + 测试。
3. 前端：粘贴 / 拖入 + E2E。
4. 导出、备份 + 测试。
5. 文档（README 使用说明、模块地图）、`feature_list.json` 证据、进度日志。

## 十一、实现时的补充（2026-11-14）

- 浏览器给剪贴板截图的名字都是 `image.png`：这类通用名字当作「没有名字」，用日期时间命名。
- 请求体超限时，原来是读到一半就回 413，连接会被重置，浏览器只看到「连不上」。改为把剩下的读完（丢弃，不占内存）再回 413，所有写接口都受益。
- 备份：每日快照 / 月度归档原本是全量重传，图片若也算进去会每天重传，所以图片只进 `latest/`（第六节第 8 条的「只传一次」靠这个保证）。
- `![[图片]]` 的「先笔记目录、再 attachments/」：前端不知道文件在不在，读文件接口支持 `?fallback=` 备选位置；导出时后端直接按顺序找。
- 没有笔记上下文的渲染（AI 对话里的 Markdown 等）只显示网络图片，本地路径显示成「[图片：说明]」。
