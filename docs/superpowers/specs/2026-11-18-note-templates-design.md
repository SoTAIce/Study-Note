# 统一笔记模板 设计方案

日期：2026-11-18
状态：**已批准（2026-11-19）**；tpl-001 已完成（见第十二节），tpl-002 待做
对应条目：tpl-001、tpl-002（`feature_list.json`）

## 一、要解决的问题

笔记大多是 Claude、GPT、Gemini 生成后粘进来的，各家结构不一样：同一个项目里，有的章是「概述 / 实现 / 总结」，有的是「1. 背景 2. 方案」。放进连读后读起来很乱，也不好找东西。

目标是用同一套模板管住结构，从三个入口：

1. 新建笔记时选模板，预填骨架；
2. 把模板复制成提示词，交给外部 AI 按结构写；
3. 粘进来的 AI 回答结构不对时，用应用内 AI 按模板规整。

## 二、已确定的需求（2026-11-18 三轮问答）

| 问题 | 结论 |
|---|---|
| 内置模板 | 「实现详情」「学习笔记」两种 |
| 实现详情的小节 | 背景 / 设计 / 关键代码 / 踩坑 / 待办 |
| 学习笔记的小节 | 要点 / 例子 / 我的理解 / 疑问 / 简卡 |
| 模板放在哪 | 在设置里管理（增、删、改、排序） |
| 子项目和模板 | 子项目可以设默认模板；在里面新建、在连读里「在此后新建一章」都自动套用，也能临时换 |
| 小节提示 | 每个小节带「这里写什么」的提示，写成 `<!-- … -->` 注释：编辑时看得到，预览、连读、PDF 都不显示 |
| 笔记记住模板 | 写进文件头：`template: 实现详情` |
| 规整能动到什么程度 | **只搬不改**：把原文搬进模板的各小节，不增删事实、不改说法；放不进的进末尾「其他」，空着的小节标「待补」 |
| 规整的入口 | AI 面板里的按钮；往正文里粘贴大段时底部提示「要按模板规整吗？」 |
| 复制成提示词的入口 | 新建页上，选完模板旁边 |
| 提示词里的要求 | 只输出 Markdown（不要开场白和客套）；没有内容的小节写「待补」 |

## 三、数据

### 3.1 模板

存在 `data/templates.json`：

```json
{
  "templates": [
    {
      "name": "实现详情",
      "sections": [
        { "title": "背景", "hint": "为什么做、要解决什么问题" },
        { "title": "设计", "hint": "结构、流程、关键决策和取舍" },
        { "title": "关键代码", "hint": "文件路径 + 片段，说明它在流程里的位置" },
        { "title": "踩坑", "hint": "遇到的问题、原因、怎么解决的" },
        { "title": "待办", "hint": "还没做的、想改进的（- [ ] 任务）" }
      ]
    },
    {
      "name": "学习笔记",
      "sections": [
        { "title": "要点", "hint": "最重要的几条结论" },
        { "title": "例子", "hint": "能说明要点的例子或代码" },
        { "title": "我的理解", "hint": "用自己的话复述，和已知的东西联系起来" },
        { "title": "疑问", "hint": "还没弄懂的地方" },
        { "title": "简卡", "hint": "问题 :: 答案，复习时用" }
      ]
    }
  ],
  "groupDefaults": { "agent/looprun": "实现详情" }
}
```

- **为什么不放 `config.json`**：`config.json` 里有 API 密钥，备份不传它。模板和子项目默认值不含密钥，单独一个文件就能和笔记一起备份（与复习记录同样处理）。
- **文件不存在时**：用内置的两种，第一次修改时才写盘。
- **模板名**：规则和组名相同（不能含 `\ : * ? " < > |`，不超过 40 字），不能重名，不区分大小写比较。
- **小节**：至少一个，标题不能重复。
- **「学习笔记」的「简卡」一节**：预填示例行 `问题 :: 答案`，沿用现有知识简卡的写法。

### 3.2 笔记记住模板

文件头加一行 `template: 实现详情`：

- 只改这一行，正文和其它键逐字节保留，写法与 `group:` 一样。
- 删掉这一行就是「不用模板」。
- 索引里多一列 `template`，可以从 Markdown 重建。

### 3.3 子项目的默认模板

- 存在 `templates.json` 的 `groupDefaults` 里，键是组名。
- 分组改名、删除时跟着改或删（与 groups.json 一样连带子项目）。
- 模板改名时跟着改；模板删除时，默认值清掉。

### 3.4 模板改名、删除

- **改名**：笔记文件头里写的是旧名字。改名时问一次：「有 N 篇笔记用的是旧名字，要一起改吗？」选「改」就逐篇只改 `template:` 一行，走 store、带 baseHash，与分组改名同样处理。
- **删除**：笔记不动，文件头里的旧名字留着。这些笔记显示「模板『X』已不存在」，规整时让你另选一个。

## 四、骨架长什么样

选「实现详情」新建《looprun 主循环》，正文预填为：

```markdown
## 背景
<!-- 为什么做、要解决什么问题 -->

## 设计
<!-- 结构、流程、关键决策和取舍 -->

## 关键代码
<!-- 文件路径 + 片段，说明它在流程里的位置 -->

## 踩坑
<!-- 遇到的问题、原因、怎么解决的 -->

## 待办
<!-- 还没做的、想改进的（- [ ] 任务） -->
```

- 小节一律用 `##`。标题已经在文件头和连读的章标题里，不再写 `# 标题`。
- 注释在预览里本来就不显示（现在的 `markdown.ts` 会转义原始 HTML，所以要专门处理 `<!-- -->`，见第八节）。

## 五、入口和界面

### 5.1 设置：模板管理

现在没有统一的「设置」页（备份、AI 设置各有各的入口），所以模板管理也单独开一个面板，三个入口：

- 左栏底部图标「笔记模板」，和备份、重建索引放在一起；
- 新建页模板选择旁边的「管理模板」；
- 搜索面板（Ctrl+K）里输入「模板」。

面板的内容：

- 左边是模板列表：可以拖动排序，最上面的是新建页的默认选项。
- 右边编辑选中的模板：
  - 模板名；
  - 小节列表：标题 + 提示，可以增、删、上移、下移；
  - 底下是预览，显示骨架长什么样。
- 下方「子项目默认模板」：列出设了默认值的子项目，可以改、可以清除。也可以在左栏子项目的菜单里设。
- 按钮：「新建模板」「复制一份」「删除」「恢复内置的两种」（只补回缺的，不覆盖改过的）。

### 5.2 新建页

- 标题下面加一行「模板：[不用模板 ▾]」。
  - 打开新建页时，分组栏里是有默认模板的子项目，就预选那个模板；
  - 否则预选上次用的（记在本机浏览器），第一次是「不用模板」。
- 选了模板，正文框预填骨架（正文已经写了东西时先问要不要覆盖）。
- 选了模板时，旁边出现「复制成提示词」按钮，见 5.3。
- 创建时文件头写 `template:`。

### 5.3 复制成提示词

把下面这段复制到剪贴板（主题取新建页上的标题；标题空着就写「（主题自己补上）」）：

```text
请就「looprun 主循环」写一篇笔记，严格按下面的结构输出：

## 背景
（为什么做、要解决什么问题）
## 设计
（结构、流程、关键决策和取舍）
## 关键代码
（文件路径 + 片段，说明它在流程里的位置）
## 踩坑
（遇到的问题、原因、怎么解决的）
## 待办
（还没做的、想改进的（- [ ] 任务））

要求：
- 只输出 Markdown 正文，从第一个「## 背景」开始，不要开场白、不要结尾的客套话；
- 小节标题、顺序和级别都不要改，不要加别的 ## 小节（小节里可以用 ### 细分）；
- 某个小节没有可写的内容就只写「待补」，不要编造。
```

用法：把它发给 Claude、GPT 或 Gemini，回答整段复制回来，粘进正文。

### 5.4 连读和子项目

- 在设了默认模板的子项目里新建、在连读里「在此后新建一章」，新章自动套用默认模板，文件头写 `template:`。
  - 连读里 + 的输入框旁边可以临时换模板。
- 左栏子项目的菜单里多一项「默认模板…」。

### 5.5 按模板规整（tpl-002）

**入口：**
- 右栏 AI 面板「改稿」一组里加「按模板规整」：
  - 模板默认是这篇文件头里的；没有的话用所在子项目的默认模板；再没有就让你选。
- 往正文里一次粘贴超过 400 字、且粘贴前正文几乎是空的（空白，或只有模板骨架）时，底部出现提示条：「要按『实现详情』规整刚粘贴的内容吗？［规整］［不用］」。
  - 这篇没有模板时，提示条里可以选一个。
  - 10 秒内不点就自动消失，不打扰继续写。

**怎么做到「只搬不改」：AI 只给分配方案，正文由应用自己拼。**

1. **切块**：应用把正文切成块，按 Markdown 顶层块切，每块编号。一个块是一段、一个列表、一个代码块、一个表格、一个引用或一个标题。
2. **AI 只回分配方案**：把编号块和模板小节名发给应用内 AI，只要它回一个 JSON：
   - 每个块放进哪个小节，比如 `{"背景": [1, 2], "设计": [4, 5, 6], "drop": [0, 3]}`；
   - `drop` 只允许是标题块：AI 原来的「## 1. 背景」这类标题，由模板的小节标题代替。
3. **应用校验并拼接**：
   - 每个块按原文逐字放进对应小节，同一小节里保持原来的先后顺序；
   - 没分配到的块放进末尾的「## 其他」；
   - 空着的小节写「待补」；
   - 校验不过就不写入，提示原因（编号重复、越界、把非标题块放进 drop、小节名不在模板里）。
4. **骨架和原标题怎么处理**：
   - 正文里已有的模板骨架（同名 `##` 标题、模板提示注释）先拿掉再切块，拼的时候重新生成；
   - 原文里的 `###` 及以下标题当普通块搬，可以留在小节里做细分。
5. **预览和写入**：
   - 先显示前后差异：复用历史版本面板的差异视图，左边原文，右边规整后，并标出每个小节收了哪几块；
   - 点「应用」才整篇替换；
   - 写入走现有的「AI 整篇替换」流程：存历史版本（reason: ai），可以「撤销 AI 改写」，Ctrl+Z 也能撤回；
   - 文件头补上 `template:`。

**这样做的好处**：正文的每个字都来自原文，AI 改不了一个字，也编不出东西；最坏的情况只是分错小节，从差异里一眼能看出来。

**代价**：
- 一个列表或一段话里如果混着两个小节的内容，只能整块放进一个小节，不会拆开；
- 原文用 `**背景**` 这种加粗段落代替标题时，它是普通块，会被搬进小节，不会被当成标题删掉。这两种情况在差异里都看得到，可以自己再改。

## 六、接口

| 接口 | 说明 |
|---|---|
| `GET /api/templates` | `{ templates, groupDefaults }` |
| `PUT /api/templates` | 整体保存（带 `version`，防止两个标签页互相覆盖）；校验名字和小节 |
| `POST /api/templates/rename` | `{ from, to, updateNotes }`：改名，可选连带改笔记文件头；返回改了几篇 |
| `PUT /api/templates/default` | `{ group, template \| null }`：设或清子项目默认模板 |
| `POST /api/notes`、`POST /api/book/chapters` | 多接受 `template`；不传时，在有默认模板的组里自动套用（骨架 + 文件头） |
| `PUT /api/notes/:id` | 多接受 `template`（`null` = 去掉这一行），与 `group` 一样只改文件头那一行 |
| `POST /api/ai/arrange` | `{ id, template, baseHash }` → `{ blocks, plan, body }`。服务端切块、请求 AI、校验、拼好；**不写盘**，由前端预览后走整篇替换保存 |

## 七、不变的约束

- 模板只决定预填什么、怎么规整；笔记照旧是普通 Markdown。删掉 `templates.json`，笔记一个字都不受影响。
- 写笔记一律走 `store.ts`，带 baseHash，原子写。
- AI 改笔记：先出差异，人批准后写入，可撤销（硬性约束 6）。
- 不新增运行时依赖；颜色只用 token；浅色和深色都要检查。

## 八、要顺带处理的地方

- **预览里藏起 `<!-- 注释 -->`**：现在 `markdown.ts` 会把原始 HTML 转义成文字，注释会原样露出来。
  - 改成：渲染时去掉 HTML 注释（只去掉 `<!--` 到 `-->`，其它原始 HTML 照旧转义）；代码块和行内代码里的不动。
  - 预览、连读、导出 PDF 共用这一处。
  - 单测要覆盖：注释里藏 `<script>`、没闭合的 `<!--`。
- **列表摘要、搜索**：去掉注释，免得每篇模板笔记的摘要都是「为什么做、要解决什么问题」。
- **AI 面板的其它动作**（润色、精简等）：发给模型前不去掉注释，原样保留，免得改写后提示丢了。

## 十一、风险

- **注释藏起来了，空小节就看不出来**：在编辑页能看到，在预览和连读里只剩一个小节标题。规整时写的「待补」会显示出来，手写的空小节没有提示。先这样，用着不顺再加「空小节淡显」。
- **外部 AI 不听话**：比如改了小节名、多加小节。这正是规整要处理的：粘进来以后点规整即可。
- **切块粒度**：见 5.5 的代价。
- **模型回 JSON 的稳定性**：小模型可能回坏 JSON。坏了就报错、不写盘，可以重试或换模型。

## 十二、实现记录

### tpl-001（2026-11-19 完成）

按方案做完，以下几处和方案字面不同，原因如下：

- **「简卡」一节不预填示例行**：方案写的是预填 `问题 :: 答案`。实际上这一行会被当成一张真卡片，每建一篇学习笔记卡片墙里就多一张「问题」卡。所以示例写进提示注释里（`一行一张：问题 :: 答案，复习时用`），简卡解析跳过注释（`cards.ts`）。
- **自动套用默认模板只在正文为空时**：`POST /api/notes` 没传 `template`、正文又不为空（比如从别处新建、带了正文）时，不自动套用，免得文件头写着模板而正文不是它的结构。新建页、连读新建章都会显式传 `template`（选「不用模板」时传 `null`），不受影响。
- **模板排序用上移 / 下移按钮**：方案写的是拖动。按钮在键盘和读屏下也能用，实现也小；以后觉得不顺手再加拖动。
- **改名在保存时识别**：面板里直接改模板名，保存时按「载入时的名字 ≠ 现在的名字」逐个调改名接口（有笔记在用就先问要不要一起改），再整体保存小节和顺序。
- **编辑页显示模板名**：方案 3.4 说「显示模板『X』已不存在」，没说放哪。放在编辑页标题下方的那一行（分组旁边）；模板还在时显示模板名，不在了显示黄色提示。
- **新建页的正文框关掉了字体连写**：等宽字体会把 `<!--`、`-->` 画成箭头，提示看着像乱码（编辑页、连读本来就关了）。

数据与接口：

- `data/templates.json`：`{ version, templates, groupDefaults }`，原子写；写坏了接口报 500 并说明怎么办，不会悄悄当成内置的覆盖掉。
- 备份：上传到云端的 `_templates/templates.json`，跟着 latest / 每日快照 / 月度归档；不出现在「从快照恢复笔记」的列表里。
- 索引：`notes.template` 列（SCHEMA_VERSION 6，旧库自动重建）；全文索引、摘要、简卡解析都去掉 HTML 注释。
- 渲染：`markdown.ts` 的原始 HTML 规则改为「完整的 `<!-- … -->` 整段去掉，其余照旧转义」；没闭合的 `<!--` 照旧显示成文字，代码块和行内代码里的不动。

验证：见 `feature_list.json` tpl-001 的 evidence 与 `docs/测试文档-2026-11.md` 第十一节。
