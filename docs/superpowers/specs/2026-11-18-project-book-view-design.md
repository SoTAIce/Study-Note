# 子项目与连读（项目开发笔记）设计方案

状态：**已批准**（2026-11-18）
对应条目：group-002、book-001、book-002、book-003（`feature_list.json`）

## 一、要解决的问题

用户在「agent」分组下维护一个项目（looprun）的开发笔记：`looprun 实现详情`、`agent trace 实现详情`、`踩坑记录`……现在：

- 分组只有一层，没法表达「agent 下的 looprun 项目」；
- 要同时看几篇只能开多个标签页来回切，一次只看得到一篇；
- 笔记之间的先后顺序（先读哪篇）没有地方记。

## 二、问答结论（2026-11-18，四轮）

| 问题 | 用户选择 |
|---|---|
| 多篇怎么看 | **上下连成一篇长文**，左边目录可跳转 |
| 「链路」指什么 | **有先后顺序的章节** |
| 连读时能不能改 | **能直接改**：点哪章改哪章 |
| 项目放在哪一层 | **分组下再分子项目**：`group: agent/looprun`，最多两层 |
| 章节顺序由什么定 | **项目里一篇「目录」笔记**：目录即总览，链接顺序就是章节顺序 |
| 连读附加功能 | 目录含各章小标题；整个项目导出 PDF；章间 `[[链接]]` 本页跳转 |
| 左栏点子项目 | **直接进连读**；▸ 展开单篇列表，点单篇照常打开 |
| 目录链到别的项目的笔记 | **照样连读，标出来源** |
| 点父分组 agent | **包含所有子项目的笔记**，每条标子项目名 |
| 父分组改名 / 删除 | **子项目跟着一起变**；删除前确认框列出影响范围 |
| 三件事的先后 | 连读 → 模板（tpl-001）→ 演示（help-001） |

## 三、范围

本方案只做**子项目 + 连读**（含就地编辑和整本导出）。同一轮讨论里提出的另外两件事各自立条目、各自写方案：

- tpl-001 统一模板（新建预填、复制给外部 AI 的提示词、粘贴后 AI 规整）；
- help-001 内置使用手册 + 快捷键 / 语法速查面板。

## 四、数据模型（全部写在 Markdown 里，索引可重建）

### 4.1 子项目 = 带斜杠的组名

```yaml
group: agent/looprun
```

- **规则**：
  - 组名可以含**一个** `/`，左边是父分组，右边是子项目，最多两层；
  - 每一段单独按现有规则校验：非空，≤ 40 字，不能含其它保留字符，不能叫「未分组」或「none」；
  - 斜杠两边的空白会被去掉：`agent / looprun` 规整为 `agent/looprun`；
  - 比较时不区分大小写，和现在一样。
- **旧数据**：以前的组名禁止 `/`，所以已有数据不需要迁移。
- **`groups.json`**：子项目也登记成一条，例如 `{ "name": "agent/looprun", "order": … }`。
  - 父分组即使没有直接属于它的笔记，只要有子项目，就照常显示，不显示为「空分组」。
  - 排序只在同一层之间比较。

### 4.2 目录笔记 = `type: index`

```markdown
---
title: 目录
group: agent/looprun
type: index
---

looprun 是一个……（这些文字是项目总览，显示在连读最前面）

1. [[looprun 实现详情]]
2. [[agent trace 实现详情]]
3. [[踩坑记录]]
```

- **类型**：`NoteType` 新增 `index`。
  - 一个项目（任意一层的分组都行）里，`type: index` 的那篇就是目录。
  - 兜底：没有 `type: index` 时，标题正好是「目录」的那篇也算目录，方便直接手写。
  - 一个项目里有多篇目录时，取最早创建的那篇，连读顶部提示「有 N 篇目录，用的是《…》」。
- **章节顺序**：目录正文里 `[[链接]]` 第一次出现的顺序。
  - 重复的链接只算一次。
  - 指向目录自身的链接忽略。
  - 链接的解析沿用现有双链逻辑（按标题）。
- **总览**：目录笔记本身原样渲染，作为连读的第一节。链接还显示成链接，点了跳到对应章节。
- **链接指向不存在的笔记**：在连读里占一个位置，显示「还没有这篇」和「新建」按钮。
- **项目里没写进目录的笔记**：放在最后「未排入目录」一栏，按创建时间排序。每篇有「加入目录」按钮，点了会在目录末尾追加一行 `- [[标题]]`。
- **项目里没有目录**：按创建时间连读，顶部提示「生成目录」。点了会新建一篇 `type: index` 的目录笔记，按当前顺序写出全部链接。
- **目录链到别的分组的笔记**：照常作为一章，标题旁标「来自 agent/trace-ui」，也可以就地修改。

所有写入（追加链接、生成目录、新建章节）都经 `store.ts`，带 baseHash。

## 五、接口

| 接口 | 作用 |
|---|---|
| `GET /api/notes?group=agent` | **改**：父分组也匹配 `agent/*`，即 `lower(group_name) = ? OR lower(group_name) LIKE ? || '/%'`（转义 `%` 和 `_`）。搜索的分组筛选同样处理 |
| `GET /api/book?group=agent/looprun` | **新**：返回见下方 |
| `POST /api/book/chapters` | **新**：`{ group, after?: noteId, title }`。新建笔记（归入该组）后，在目录里 `after` 那一行之后插入链接；没有目录就先生成一篇。两次写入，第二次冲突时笔记已经建好，返回 409 并说明「笔记已建好，目录没改上」 |
| `POST /api/book/index` | **新**：生成目录，或把若干篇追加进目录 |
| 改名、删除分组 | **改**：改名 `agent` 时，`agent/*` 一起改，逐篇只改 `group:` 那一行。删除（取消分组）同样连带子项目，接口先返回影响范围，供确认框显示 |

`GET /api/book` 返回：

```json
{
  "index": { "id": "…", "title": "…", "body": "…", "hash": "…" },
  "chapters": [{ "id": "…", "title": "…", "group": "…", "body": "…", "hash": "…", "foreign": false }],
  "missing": ["…"],
  "unlisted": [],
  "duplicateIndexes": 0
}
```

`index` 在没有目录时为 `null`。正文一次全部返回；一个项目通常几十篇以内，见第八节的性能要求。

章节修改直接用现有的 `PUT /api/notes/:id`（带 baseHash），不新增保存接口。

## 六、界面

### 6.1 左栏

```
▾ agent                 (12)
   ▸ looprun            (4)   ← 点名字：连读；点 ▸：展开单篇
   ▸ trace-ui           (2)
   · （6 篇直接属于 agent）
▸ 课程
```

- **点父分组的名字**：和现在一样筛选列表（包含子项目，每条标子项目名）。列表顶部多一个「连读」按钮，用于父分组自己的目录或直接属于它的笔记。
- **点子项目的名字**：中间区域打开连读。
- **新建子项目**：父分组右键菜单（或「⋯」）→「新建子项目」。也可以在新建笔记的分组栏里直接写 `agent/looprun`，分组栏的候选里会出现已有的子项目。
- 展开 / 折叠状态记在 localStorage（`study.groupTreeOpen`），只为方便，丢了不影响功能。

### 6.2 连读页

```
┌ 目录 ─────────────┐┌─────────────────────────────────────┐
│ 总览               ││ agent / looprun        [导出整本] [⋯]│
│ 1 looprun 实现  ◀ ││ ── 总览（目录笔记正文）──             │
│   · 主循环         ││ ── 1 looprun 实现详情   [编辑][↗][+]  │
│   · 重试策略       ││   渲染好的正文……                      │
│ 2 agent trace      ││ ── 2 agent trace 实现  来自 trace-ui │
│ 3 踩坑记录         ││   ……                                  │
│ 未排入目录 (1)     ││ ── 未排入目录：xxx   [加入目录]       │
└───────────────────┘└─────────────────────────────────────┘
```

- **左侧目录**：
  - 显示章节，以及每章里的 `##` / `###` 小标题；
  - 滚动时高亮当前所在的位置；
  - 点击跳转；
  - 窄屏时收进顶部的「目录」按钮。
- **章节头**：
  - 序号和标题；
  - 「来自 …」标记（来自别的项目时）；
  - 「编辑」；
  - 「单独打开」（↗），用普通标签页打开；
  - 「在此后新建一章」（+）。
- **就地编辑（book-002）**：
  - 双击正文或点「编辑」，这一章原地变成编辑框；
  - 编辑框用现有编辑器组件，快捷键、贴图、`[[` 补全、撤销都能用；
  - 同一时间只有一章在编辑：点另一章的「编辑」时，先保存当前这章；
  - Esc、点编辑框以外、`Ctrl+S` 都会保存并恢复成渲染状态；
  - 保存走现有的保存与冲突流程（save-plan + baseHash）。冲突时用现有的冲突提示，这一章停在编辑状态。
- **外部修改**：
  - 通过 SSE 推来的修改：正在编辑的那章走冲突流程，其它章直接刷新；
  - 目录笔记变了就重新取整本。
- **链接跳转**：章节里的 `[[链接]]` 指向本书内的章节时，在本页滚过去，地址栏的 hash 跟着变；指向书外的笔记时，照常打开。
- **简卡、图片、任务复选框**：和预览里一样渲染。复选框能点，点了改的是那一章的源文件。
- **键盘与读屏**：
  - 章节用 `<section aria-labelledby>`，目录用 `<nav>`；
  - `[` / `]` 跳到上一章 / 下一章，正在编辑时不响应。

### 6.3 整本导出（book-003）

「导出整本」沿用 export-001 的打印流程（`--remote-debugging-pipe` + `Page.printToPDF`）和版式（手机版或 A4，浅色或深色）：

- 第一页是书名（项目名）和目录页；
- 每章从新的一页开始；
- PDF 书签按「章 → 小标题」两级生成；
- 书内的 `[[链接]]` 变成文档内跳转，指向书外的链接变成普通文字。

这一项也算部分完成了 export-002（「分组合并导出」）：任何分组都能连读，所以都能整本导出。export-002 剩下的只有「按标签导出」，到时把它的描述改小即可。

## 七、不变的约束

- 子项目和目录都写在 Markdown 文件里，删掉 SQLite 后重建索引能得到同样的结果。
- 所有写入经 `store.ts`，带 baseHash，原子写；改名、删除分组时逐篇只改 `group:` 一行。
- 渲染沿用 `markdown.ts`（转义 HTML、过滤危险链接）。
- 不新增运行时依赖；颜色只用 token；浅色和深色都要检查。

## 八、测试与验收

- **单元测试**：
  - 组名带斜杠的校验与规整（`a/b`、`a / b`、`a/b/c` 拒绝、`/b` 拒绝、各段长度）；
  - 父分组前缀匹配要转义 `%` 和 `_`；
  - 目录解析：顺序、去重、忽略自身、标题兜底、多篇目录；
  - 在 `after` 之后插入链接的文本改写，保留原换行符和列表样式。
- **接口测试**：
  - `GET /api/book` 的各种情况（无目录、缺章、外来章、未排入目录）；
  - `POST /api/book/chapters` 正常、冲突；
  - 父分组改名、删除连带子项目；
  - `?group=agent` 包含子项目。
- **E2E**：
  - 建子项目，左栏出现树；
  - 点子项目进连读，顺序和目录一致；
  - 点目录跳转；
  - 双击一章，改完按 Esc，确认文件已改；
  - 「在此后新建一章」后，目录多一行；
  - 章间链接在本页滚动；
  - 导出整本 PDF，检查书签数。
- **基准**：一个 100 章、每章约 3000 字的项目，`GET /api/book` 加上首屏渲染不超过 1 秒。超了就改成章节进入视口时才渲染。

## 十、风险与待定

- **同名笔记**：两篇标题相同时，`[[标题]]` 解析到哪篇沿用现有规则。连读顶部会提示目录里有歧义的链接。
- **最多两层**：以后真需要三层再放开。斜杠语法本身支持多层，到时只需要放宽校验和左栏树。
- **大项目**：见第八节的基准，超过就改成懒渲染。

## 十一、实现记录（与方案的出入）

### group-002（2026-11-18）

- 组名在 `parse.ts` 读入时就规整（`agent / looprun` → `agent/looprun`），索引和筛选只认一种写法。
- `GET /api/groups` 每项多了 `total`（连同子项目的篇数），左栏父分组显示 total。
- 树的折叠状态存的是「折叠了哪些」（`study.groupTreeCollapsed`），默认全部展开。

### book-001（2026-11-18）

- 缺章不单独放 `missing` 数组，而是作为 `{ kind: "missing", title }` 留在 `chapters` 里原来的位置，顺序不丢。
- 多篇目录返回其余目录的标题 `otherIndexes`（方案写的是计数），提示里能直接说出是哪几篇。
- 生成的目录标题是「<子项目名> 目录」（如「looprun 目录」），避免每个项目都有一篇叫「目录」的笔记、双链分不清；手写的「目录」照样认。
- 本页跳转没有改地址栏的 hash：应用目前没有按地址路由，加 hash 会和现有的返回逻辑打架。跳转后焦点落在目标章标题上（读屏能读出来）。
- 连读里的任务复选框暂时只读：点它要改源文件，归到 book-002 的就地编辑一起做。
- 懒渲染没有做：基准（`pnpm bench:book`）100 章 × 3000 字组装 + 渲染约 65ms，远低于 1 秒。
- 在连读里点「新建笔记」，分组栏预填正在读的项目。
- **没做**：第十节说的「目录里有同名歧义链接时在顶部提示」。现在同名时优先取本项目里的那篇，其次全库最早创建的；提示留到有人真遇到再加（记为风险）。
