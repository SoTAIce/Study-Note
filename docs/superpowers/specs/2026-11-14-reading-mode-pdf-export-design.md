# 阅览模式与导出手机可读 PDF（reading-001 / export-001）设计

日期：2026-11-14 · 状态：待批准（第九节有几处需要用户决定）

## 一、要解决什么

1. **在手机上读笔记**：用户想把笔记导出成 PDF，传到手机上读。普通 A4 PDF 在手机上要么字小得看不清，要么得不停地放大、左右拖。PDF 要按手机阅读来排版。
2. **在电脑上好好读**：本机也要一个专门「读」的模式。不显示编辑器和侧栏，排版舒服，长笔记能快速跳到某一节。

## 二、现状

- 已有「全屏预览」（`PreviewOverlay`，`Ctrl+Shift+F`）：
  - 能做到：预览铺满窗口，A− / A+ 调字号（记在 localStorage），Esc 退出，双链和标签可以点。
  - 没有：目录、阅读进度、上一篇 / 下一篇、行宽调节、记住读到哪里。
- Markdown 渲染在 `web/src/lib/markdown.ts`，用的是已有依赖 `marked`。它是纯函数：会转义原始 HTML、过滤危险链接，并处理双链和标签。
- 没有任何导出 PDF 的功能。浏览器自带的 Ctrl+P 打出来的是整个三栏界面，没法用。

## 三、目标

1. **阅览模式**：
   - 一键进入，只显示正文。
   - 正文列宽适合阅读，按标题自动生成目录，有阅读进度。
   - 可以上一篇 / 下一篇连续读。
   - 记住每篇读到的位置。
2. **导出手机可读 PDF**：
   - 在编辑器工具栏点「导出 PDF」，选「手机阅读」版式，直接下载 `标题.pdf`。
   - 传到手机后，在微信、文件 App、iBooks、WPS 里打开，**不用放大就能读**。
   - 代码和表格**不会被截断**。
   - 有标题书签，可以按目录跳转。
3. **两边看起来一致**：阅览模式和 PDF 共用一套「阅读排版」样式，在屏幕上看到的就是导出来的样子。
4. **离线可用，不加新依赖**：不打包 Chromium，不引入 PDF 库，中文字体也不额外打包。

## 四、非目标

- 不做 EPUB、Word 导出（以后需要再说）。
- 不做 PDF 内的批注、高亮回写到笔记。
- 不负责把文件传到手机（第九节第 5 条另议）。
- 阅览模式只读，不在里面编辑。

## 五、反目标（出现这些就算失败）

- 导出的 PDF 在手机上必须放大才能读，或者需要左右拖。
- 长代码行、宽表格被裁掉看不见。
- 导出把笔记里的原始 HTML 当成真的 HTML 执行（违反 AGENTS.md 约束 5）。
- 导出的不是磁盘上最新的内容（有未保存的修改时，导出的是旧版本）。
- 为了导出，给应用加上几百 MB 的依赖。

## 六、方案

### 1. 共用的阅读排版（`web/src/styles/reading.css`）

- 正文：
  - 屏幕上 18px，行高 1.75，最大行宽约 36 个汉字（`max-width: 680px`）。
  - 段落之间留出空隙，标题层级清楚。
  - 颜色全部用 `global.css` 的 token（AGENTS.md 约束 8）。
- 代码块：`white-space: pre-wrap` 自动换行，不出横向滚动条；字号比正文小一号。
- 表格：
  - 单元格文字可以换行（`overflow-wrap: anywhere`）。
  - 表格超过版心宽度时，整表字号缩小一级。仍然放不下时，打印版退回到「每行一张卡片」的竖排形式（屏幕上照常横向滚动）。
- 图片：`max-width: 100%`，打印时不在图片中间分页。
- 双链：
  - 屏幕上照常可以点。
  - PDF 里，如果目标在同一个 PDF 中，就变成可点的跳转；否则只保留文字，加一层淡下划线。
- 标签：显示为文字 `#标签`。
- 分页控制：
  - 标题不落在页尾（`break-after: avoid`）。
  - 短代码块和短表格尽量不拆到两页（`break-inside: avoid`）。

### 2. 阅览模式（把现有全屏预览升级，不另起一套）

- 入口：
  - 编辑器工具栏的「阅览」按钮。
  - 沿用 `Ctrl+Shift+F`。
  - 列表里的笔记右键或长按选「阅览」（可选）。
- 布局：
  - 正文居中。
  - 左侧是可收起的**目录**，由 h1 到 h3 生成，读到哪一节就高亮哪一节，点击可跳转。
  - 顶部是一条很细的**阅读进度条**。
  - 窄屏时目录收进抽屉。
- 操作：
  - `Esc` 退出。
  - `E` 回到编辑。
  - `←` / `→` 或 `[` / `]` 切到上一篇 / 下一篇，顺序就是中间列表当前的顺序。
  - `A−` / `A+` 调字号，沿用现有的那个设置。
  - 新增「行宽：窄 / 中 / 宽」。
- 记住位置：
  - 每篇读到的位置（滚动比例）记在 localStorage，下次进入时回到那里。
  - 这只是本机的方便功能，读不到就从头开始。
- 主题：跟随应用的浅色 / 深色。是否加「护眼暖色」见第九节第 4 条。
- 阅览模式显示的是**编辑器里当前的内容**（包括还没保存的部分），和现在的全屏预览一致。

### 3. 导出 PDF

#### 3.1 生成方式：用电脑上已经装好的浏览器在后台生成（推荐）

Windows 自带 Edge。Edge 和 Chrome 都支持在后台把一个 HTML 页面直接打印成 PDF：

```
msedge --headless=new --disable-gpu --no-pdf-header-footer --generate-pdf-document-outline --print-to-pdf=<输出.pdf> file:///<临时目录>/export.html
```

流程：

1. 点「导出 PDF」时，先把没保存的修改存掉（`doSave()`）。
2. 前端发请求 `POST /api/export/pdf { ids: [id], layout: "phone" }`。
3. 服务端从磁盘读取笔记，用同一个 `renderMarkdown` 渲染。HTML 照常转义，危险链接照常过滤。再拼上 `reading.css` 和版式参数，生成一个**完全自包含**的 HTML 文件，放进临时目录。这个 HTML 不连网，也不访问应用的接口。
4. 服务端调用上面那条命令（`child_process.spawn`，30 秒超时，参数全由服务端拼出，不包含任何用户输入），把生成的 PDF 作为下载返回，文件名是 `标题.pdf`。然后删掉临时文件。
5. 浏览器的查找顺序：
   1. 环境变量 `STUDY_PDF_BROWSER`。
   2. Windows 上 Edge 和 Chrome 的常见安装路径。
   3. macOS 的 `/Applications`。
   4. Linux 上 `PATH` 里的 chromium / chrome。
6. **找不到浏览器时自动退回**：前端拿到同样的 HTML，在隐藏的 iframe 里打开浏览器的打印对话框。用户在对话框里选「另存为 PDF」，得到的版式完全一样，只是多点一下。

已经在开发环境里试过：100×178mm 的页面生成正确，中文正常，标题书签自动生成。

为什么不用别的办法：

| 办法 | 问题 |
|---|---|
| 只用浏览器打印对话框 | 每次都要在对话框里选「另存为 PDF」，还要确认纸张。不过它保留下来作为退回方案 |
| 引入 jsPDF / pdfkit 一类 PDF 库 | 中文要自带字体，动辄十几 MB；排版能力弱，表格和代码难做好 |
| 打包 Puppeteer / Playwright 自带的 Chromium | 一百多 MB 的新依赖，违反「不引入新依赖」 |

#### 3.2 版式

| 版式 | 页面 | 正文 | 页边距 | 用途 |
|---|---|---|---|---|
| **手机阅读**（默认） | 100 × 178 mm | 12pt，行高 1.6 | 7 mm | 手机上按宽度适配后，字大小和手机 App 的正文差不多，不用放大 |
| A4 | 210 × 297 mm | 11pt | 18 mm | 打印到纸上 |

- 手机版式的算法：
  - 手机屏幕宽约 68mm，100mm 宽的页面按宽度适配后缩放到 0.68 倍。
  - 12pt 的正文显示出来约 8pt，和手机 App 的正文大小相近。
  - 页面高度取 16:9，在「连续滚动」模式下翻页不频繁。
- 页面内容：
  - 第一页顶部：标题、更新日期、分组、标签（可以关掉）。
  - 页脚：页码（`3 / 12`）。
- 颜色：
  - PDF 默认浅色。
  - 「深色 PDF」作为可选项，适合夜里读。
  - 正文黑白，链接用强调色。
- 字体：用系统字体。Windows 上是微软雅黑，代码用 Consolas。PDF 会只嵌入用到的那部分字形，手机上没有这些字体也能正常显示。

#### 3.3 界面

- 编辑器工具栏加「导出」按钮，阅览模式顶栏也有一个。
- 点击后弹出一个小面板：
  - 版式：手机阅读 / A4，默认手机，记住上次的选择。
  - 选项：包含标题信息、深色。
  - 「导出」按钮。
  - 生成过程中按钮显示「生成中…」。完成后浏览器下载，并提示「已导出：标题.pdf」。
  - 失败时说清原因。比如「没找到 Edge 或 Chrome，已改用打印对话框」。

### 4. 安全与约束对照

| 约束 | 怎么满足 |
|---|---|
| 1 Markdown 是唯一真源 | 导出只读文件，不写入任何东西 |
| 4 只监听 127.0.0.1，闸门不放宽 | 新接口照常走 Host / Origin / Content-Type 闸门。后台浏览器打开的是本地 `file://`，不经过 HTTP |
| 5 渲染转义原始 HTML | 服务端复用同一个 `renderMarkdown`。生成的 HTML 加上 `Content-Security-Policy: script-src 'none'` 的 meta |
| 7 不加运行时依赖 | 只用 Node 自带的 `child_process` 和系统里已有的浏览器 |
| 8 设计语言 | `reading.css` 只用 token；`design-rules.test.ts` 照常检查 |
| 9 Windows 优先 | 路径一律用 `path`；Edge 路径按 Windows 优先探测 |

## 七、验证计划

- 单元测试：
  - 生成导出 HTML 的纯函数：转义、CSP、版式参数、双链变成纯文字或同 PDF 内的跳转。
  - 查找浏览器的函数：注入一个假的文件系统来测。
  - 阅览模式的纯函数：目录提取、当前所在章节计算、上一篇 / 下一篇。
- 接口测试：`POST /api/export/pdf`。
  - 找不到浏览器时返回明确的错误码，前端据此退回打印对话框。
  - 参数非法时返回 400。
  - 笔记不存在时返回 404。
- 浏览器测试（E2E 里用 `STUDY_PDF_BROWSER` 指向测试用的 Chromium）：
  - 导出 PDF：下载到的文件以 `%PDF` 开头，页面尺寸约 283 × 505pt（100 × 178mm），有书签。
  - 一段很长的代码行，在 PDF 文本里能完整找到。
  - 阅览模式：
    - 点目录能跳到对应小节。
    - `→` 能切到下一篇。
    - 退出后再进入，回到上次读的位置。
    - 窄屏下目录收进抽屉。
  - 截图：阅览模式的浅色、深色、窄屏各一张，PDF 的第一页渲染成图片一张。
- 人工验收：导出一篇带表格和代码的长笔记，传到手机上，分别用微信和系统的文件 App 打开，看是否不用放大就能读。

## 八、分期

1. **reading-001 阅览模式**：先做。PDF 的排版样式也在这一步定下来。
2. **export-001 单篇导出 PDF**：后台浏览器生成，找不到时退回打印对话框。
3. **export-002 多篇合并导出**（视第九节第 3 条决定）：整个分组或标签导出成一本 PDF，带目录页。目录和书签可以跳转，同一本里的双链也可以点。

## 九、需要用户决定

1. **生成方式**：用 Edge 在后台一键生成（推荐，找不到时自动退回打印对话框），还是只用浏览器打印对话框（实现更简单，每次多点一步）？
2. **手机版式**：100 × 178mm、正文 12pt 这个默认值可以吗？你的手机屏幕偏大（比如 Pro Max、折叠屏）还是偏小？另外，A4 版式要不要保留？
3. **多篇合并**：要不要一次导出整个分组或标签，合成一本带目录的 PDF？这在手机上连续读很方便，但工作量差不多翻倍。
4. **护眼暖色**：阅览模式和 PDF 要不要加一个米黄底色的「护眼」主题？这需要在 DESIGN.md 里加一组颜色 token。
5. **怎么到手机上**：导出后自己用微信或 AirDrop 传，还是希望自动放进已经配好的 WebDAV（比如坚果云）同步目录，让手机直接看到？后者另记一个功能。
