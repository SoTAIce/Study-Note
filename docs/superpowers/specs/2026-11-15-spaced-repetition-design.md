# 间隔复习（闪卡）设计

日期：2026-11-15 · 状态：草案，待用户批准（第九节需要你决定）

## 一、要解决什么

现在笔记只是「记下来」。学过的东西过几周就忘，而应用不会提醒你复习：

- 右栏 AI 的「出题」只能出一次性的题，答完就没了，没有「什么时候再考我」。
- 想复习只能自己翻笔记，不知道哪些快忘了、哪些已经很熟。

目标：**在笔记里随手写下问答，应用按遗忘规律每天安排该复习的卡片**，复习几分钟就能把要记的东西长期记住。

## 二、现状（和这个功能有关的部分）

| 地方 | 现在的情况 | 对本功能的影响 |
|---|---|---|
| 真源（AGENTS.md 约束 1） | Markdown 是唯一真源，SQLite 只是可重建的索引 | 卡片内容必须写在 .md 里；复习记录要存成文件，不能只在 SQLite 里 |
| 笔记 id | 应用建的笔记 frontmatter 都有 `id`；外部放进来、没写 id 的笔记用路径算 id，第一次在应用里保存时写入 | 卡片用「笔记 id + 问题」识别，改文件名 / 换文件夹不丢复习记录 |
| 索引（`server/indexer.ts`） | 启动时只重新索引改过的文件（perf-006） | 卡片跟着笔记一起解析、一起进索引 |
| AI（`server/ai.ts`） | 有「出题」模式；AI 插入正文可撤销（`Ctrl+Z`） | 「AI 生成卡片」可以复用插入通道：你勾选后才写入，能撤回（约束 6） |
| 备份（`server/backup.ts`） | 扫 `data/notes` 里的 .md 和图片 | 复习记录文件要额外加进备份，否则换电脑后复习进度丢失 |
| 首页 / 左栏 | 有「全部笔记 / 收件箱 / 时间流 / AI 对话 / 回收站」 | 加一个「复习」入口和首页的「今日复习」 |

## 三、目标

1. 在任意笔记里用简单语法写卡片（单行问答、多行问答、挖空），不需要单独的卡片编辑器。
2. 每天打开应用，首页显示「今日复习 N 张」，点进去一张张过：先看问题、想一想、翻开答案、按记得的程度打分。
3. 按记忆规律安排下次复习：记得越牢，间隔越长（1 天 → 3 天 → 1 周 → 1 个月……），忘了就很快再出现。
4. 可以只复习某个分组 / 标签 / 某一篇笔记（考前集中复习一门课）。
5. 预览里卡片有明显样式，能看到「下次复习：3 天后」。
6. 复习进度随 WebDAV 一起备份。
7. （第二阶段）AI 从一篇笔记里抽取卡片，你勾选后写进笔记。

## 四、非目标

- 不做 Anki 导入 / 导出（以后需要再说）。
- 不做卡片里的音频、图片遮挡（图片本身照常显示）。
- 不做多设备实时同步（靠现有的 WebDAV 备份恢复）。
- 不做学习时长、番茄钟等统计。

## 五、反目标（出现这些就算失败）

- 往你的 Markdown 里写调度数据（如 `<!--SR:2026-11-20,3,250-->` 这种注释）。笔记要保持干净，换编辑器打开也看不到奇怪的东西。
- 改了文件名、移了文件夹、改了答案后，复习记录丢失。
- 普通文字被误认成卡片（比如 C++ 的 `std::vector`、代码块里的内容）。
- 复习记录只存在 SQLite 里，删了索引就没了。
- 一天弹出几百张新卡，复习变成负担。

## 六、方案

### 1. 卡片怎么写（三种语法，和 Obsidian 的 Spaced Repetition 插件兼容）

**单行问答**：问题和答案用前后带空格的 ` :: ` 隔开。

```markdown
梯度下降的更新公式 :: w ← w − η·∇L(w)
```

**多行问答**：问题和答案之间单独一行 `?`，到空行结束。

```markdown
贝叶斯公式是什么？各项含义？
?
P(A|B) = P(B|A)·P(A) / P(B)
P(A) 是先验，P(A|B) 是后验。
```

**挖空**：一行里用 `{{ }}` 包住要记的部分，每个挖空单独成一张卡（复习时其余挖空照常显示）。

```markdown
Transformer 用 {{自注意力}} 建模序列中任意两个位置的关系，用 {{位置编码}} 注入顺序信息。
```

规则：

- 代码块（``` / ~~~）和行内代码里的内容一律不算。
- ` :: ` 两边必须有空格，所以 `std::vector`、`a::b` 不会被误认。
- 列表项里也可以写卡片：`- 名词 :: 解释`。
- 卡片在预览、阅览模式、导出的 PDF 里显示成「问题 / 答案」两栏的卡片样式，挖空显示为带底色的文字。

### 2. 卡片怎么识别（不往笔记里写 id）

- 卡片 id = `笔记 id` + 卡片类型 + 规范化后的问题文字（去掉多余空白）算出的短 hash。
- 改答案不影响 id：复习记录保留。
- 改了问题：按「同一篇笔记、位置相同、文字相似度 ≥ 60%」认成同一张卡，继承复习记录；对不上的当新卡。
- 文件改名、移动文件夹：笔记 id 不变，卡片 id 不变。
- 删掉卡片：记录留在日志里不再用；同样的卡片写回来会接着用原来的记录。

### 3. 复习记录存在哪（真源是文件）

- `data/review/log.jsonl`：只追加的复习日志，一行一次打分：
  `{"t":"2026-11-15T21:03:00+08:00","card":"c_3f9a1b2c","note":"a1b2c3d4","grade":3}`
- 启动时读日志、按算法从头重算每张卡的状态，放进 SQLite 两张表（`cards`、`review_state`），都可以重建。几万条记录重算不到 0.2 秒（写基准验证）。
- `data/review/` 加进 `.gitignore`（个人数据，约束 3）。
- 备份：`log.jsonl` 跟着 `latest/` 和每日快照一起上传（文件很小）。

### 4. 安排算法

用 **FSRS**（Anki 2023 年起的默认算法，公开参数）：

- 每张卡记「稳定性」（多久会忘到 90% 以下）和「难度」。
- 目标记住率默认 90%：到期时大约还有 90% 的概率记得。
- 打分四档：**忘了 / 困难 / 记得 / 简单**（键盘 1 2 3 4），按钮上直接显示各档的下次间隔，例如「10 分钟 / 1 天 / 3 天 / 8 天」。
- 新卡第一次学：「忘了」10 分钟后再出现，同一轮复习里会再见到。

### 5. 复习界面

- **入口**：左栏新增「复习」（带今日到期数）；首页加一张「今日复习」卡片；快捷键 `Ctrl+Shift+R`。
- **范围**：全部 / 某个分组 / 某个标签 / 当前笔记（右栏显示「这篇有 5 张卡，2 张到期」，可以只复习这篇）。
- **顺序**：先到期的旧卡，再新卡；新卡每天最多 20 张（可调），旧卡每天最多 200 张。
- **一张卡的流程**：显示问题 → 空格 / 点击翻开答案 → 按 1~4 打分 → 下一张。卡片下方有来源笔记链接，点了打开原笔记。
- `Ctrl+Z` 撤回上一次打分（日志里追加一条撤销记录，不删历史）。
- 结束页：本次复习张数、正确率、明天预计到期数。

### 6. AI 生成卡片（第二阶段）

- 右栏 AI 加「生成闪卡」：AI 读当前笔记，返回一组候选卡片（问答 / 挖空）。
- 你逐张勾选、可以改文字，确认后写到笔记末尾的 `## 闪卡` 一节（没有就新建）。
- 写入走现有的 AI 插入通道：能 `Ctrl+Z` 撤回，满足「AI 改笔记要人批准、可撤销」（约束 6）。

## 七、要改的文件

| 文件 | 改什么 |

| `server/cards.ts`（新） | 卡片解析（三种语法、代码块排除）、卡片 id、改问题后的继承匹配 |

## 八、验证

- 单测 `cards.test.ts`：三种语法；代码块 / 行内代码 / `std::vector` 不误认；改答案 id 不变；改问题按相似度继承；改文件名不变。
- 单测 `fsrs.test.ts`：用公开参考实现的数值核对间隔；四档打分的单调性（简单 ≥ 记得 ≥ 困难）。
- 单测 `review.test.ts`：日志重算结果与逐次打分一致；撤回；每日新卡上限；删索引后从日志恢复。
- 接口测试：队列、打分、撤回、范围筛选。
- 基准：5000 张卡、5 万条日志，启动重算 < 300ms（进 init.sh）。
- E2E：在笔记里写三种卡片 → 首页显示今日复习 → 复习界面翻开、打分 → 计数减少 → 重启后进度还在 → 只复习某个分组。
- 人工：在 Windows 上连续用几天，看间隔是否合理（写进 `docs/验收清单.md`）。

## 九、需要你决定的

| # | 问题 | 推荐 | 其他选择 |
|---|---|---|---|
| 1 | 卡片语法 | 三种都支持（`::`、`?`、`{{挖空}}`） | 只要单行 `::` |
| 2 | 打分档数 | 四档（忘了 / 困难 / 记得 / 简单），和 Anki 一样 | 三档（忘了 / 模糊 / 记得），更简单但间隔不够细 |
| 3 | 每天新卡上限 | 20 张（设置里可改） | 不设上限 |
| 4 | AI 生成卡片 | 放第二阶段，先把手写卡片 + 复习做扎实 | 和第一阶段一起做 |
| 5 | 复习快捷键 | `Ctrl+Shift+R` | 不要快捷键，只用左栏入口 |

## 十、实现顺序

1. `cards.ts` + `fsrs.ts` + 单测（纯函数，先把规则定死）。
2. `review.ts` + 数据库表 + 接口 + 备份。
3. 复习界面、左栏 / 首页入口、预览里的卡片样式；E2E。
4. 基准、文档、验收清单。
5. 第二阶段：AI 生成卡片。
