# 知识简卡（卡片墙 + 间隔复习）设计

日期：2026-11-15 · 状态：已批准（2026-11-15，第九节全部按推荐），第一阶段已实现（2026-11-15）；第二阶段 AI 提炼简卡记为 srs-002

> v1 是纯问答闪卡。用户 2026-11-15 改为「知识简卡」，并选了「卡片墙浏览 + 到期复习」两者结合。本版按此重写。

## 一、要解决什么

现在笔记只是「记下来」，有两个问题：

- **不好温习**：一篇笔记几千字，考前想把要点过一遍，只能从头翻。真正要记的往往就是几个概念、几条公式。
- **会忘**：学过的东西几周后就忘，而应用不会提醒你该复习什么。右栏 AI 的「出题」只能出一次性的题。

目标：**把每个知识点写成一张精简的「简卡」**（一个概念 + 几条要点）。平时在卡片墙上按科目浏览、温习；每天应用按遗忘规律推送该复习的几张，翻面回想、打分。

## 二、现状（和这个功能有关的部分）

| 地方 | 现在的情况 | 对本功能的影响 |
|---|---|---|
| 真源（AGENTS.md 约束 1） | Markdown 是唯一真源，SQLite 只是可重建的索引 | 简卡写在 .md 里；复习记录存成文件，不能只在 SQLite 里 |
| 笔记 id | 应用建的笔记 frontmatter 都有 `id`；外部放进来的笔记第一次在应用里保存时写入 | 简卡用「笔记 id + 卡片标题」识别，改文件名 / 换文件夹不丢记录 |
| 索引（`server/indexer.ts`） | 启动时只重新索引改过的文件（perf-006） | 简卡跟着笔记一起解析、一起进索引 |
| 分组 / 标签 | 已有 | 卡片墙按笔记的分组、标签筛选 |
| AI（`server/ai.ts`） | AI 插入正文可撤销 | 「AI 提炼简卡」复用插入通道：你勾选后才写入，能撤回（约束 6） |
| 备份（`server/backup.ts`） | 扫 `data/notes` 里的 .md 和图片 | 复习记录文件要额外加进备份 |

## 三、目标

1. 在任意笔记里用简单语法写简卡；别的 Markdown 编辑器（Obsidian、Typora）打开也显示正常。
2. **卡片墙**：左栏新增「简卡」，所有卡片排成网格，可以按分组 / 标签 / 关键字筛选、按熟练度排序；点卡片可展开、可跳回原笔记。
3. **今日复习**：卡片墙顶部和首页显示「今日复习 N 张」。复习时只看正面（概念名），回想后翻面看要点，按记得的程度打分；记得越牢，间隔越长。
4. 可以只复习某个分组 / 标签 / 某一篇笔记（考前集中复习一门课）。
5. 每张卡显示熟练度（新卡 / 学习中 / 熟练）和下次复习时间。
6. 复习进度随 WebDAV 一起备份。
7. （第二阶段）AI 把一篇长笔记提炼成几张简卡，你勾选、修改后写进笔记。

## 四、非目标

- 不做单独的卡片编辑器：卡片就在笔记里写、在笔记里改。
- 不做 Anki 导入 / 导出、音频、图片遮挡（卡片里的图片照常显示）。
- 不做多设备实时同步（靠现有的 WebDAV 备份恢复）。

## 五、反目标（出现这些就算失败）

- 往 Markdown 里写调度数据（如 `<!--SR:2026-11-20,3,250-->`）。
- 改文件名、移文件夹、改要点后，复习记录丢失。
- 普通引用、`std::vector`、代码块里的内容被误认成卡片。
- 复习记录只存在 SQLite 里，删了索引就没了。
- 一天推送几百张新卡，复习变成负担。

## 六、方案

### 1. 简卡怎么写

**标准简卡**：用 Obsidian 的 callout 写法，`> [!card] 概念名` 开头，后面的引用行是要点。

```markdown
> [!card] 梯度下降
> - 沿损失函数的负梯度方向更新参数
> - 公式：w ← w − η·∇L(w)
> - 学习率 η 太大会震荡，太小收敛慢
```

- 正面是 `[!card]` 后面的标题，背面是下面的内容（列表、公式、图片、代码都可以）。
- Obsidian 里显示成一个带标题的提示框；Typora、VS Code 里显示成普通引用，都不难看。
- 也可以写 `> [!card]- 梯度下降`（Obsidian 的折叠写法），效果一样。

**一行简卡**：概念和一句话解释用前后带空格的 ` :: ` 隔开，适合术语、单词。

```markdown
过拟合 :: 模型把训练数据的噪声也学进去，在新数据上表现变差
```

识别规则：

- 只认 `> [!card]` 开头的 callout；普通 `>` 引用不算。
- ` :: ` 两边必须有空格，`std::vector`、`a::b` 不算；代码块、行内代码里的内容一律不算。
- 预览、阅览模式、导出的 PDF 里，简卡显示成卡片样式（标题 + 要点，带一个熟练度小标签）。

### 2. 简卡怎么识别（不往笔记里写 id）

- 卡片 id = `笔记 id` + 规范化后的标题（去掉多余空白）算出的短 hash。
- 改要点不影响 id，复习记录保留。
- 改了标题：按「同一篇笔记、位置相同、标题相似度 ≥ 60%」认成同一张卡，继承记录；对不上的当新卡。
- 改文件名、移文件夹：笔记 id 不变，卡片 id 不变。
- 同一篇笔记里两张卡标题相同：按出现顺序加序号区分。

### 3. 复习记录存在哪（真源是文件）

- `data/review/log.jsonl`：只追加的复习日志，一行一次打分：
  `{"t":"2026-11-15T21:03:00+08:00","card":"c_3f9a1b2c","note":"a1b2c3d4","grade":3}`
- 启动时读日志、按算法重算每张卡的状态，放进 SQLite（`cards`、`review_state` 两张表，都可以重建）。
- `data/review/` 加进 `.gitignore`（个人数据，约束 3）；备份时 `log.jsonl` 跟着 `latest/` 和每日快照上传。

### 4. 安排算法

用 **FSRS**（Anki 2023 年起的默认算法，公开参数，自己实现约 150 行，不加依赖）：

- 每张卡记「稳定性」和「难度」；目标记住率默认 90%。
- 打分四档：**忘了 / 困难 / 记得 / 简单**（键盘 1 2 3 4），按钮上直接显示下次间隔，例如「10 分钟 / 1 天 / 3 天 / 8 天」。
- 熟练度：从没复习过是「新卡」，稳定性 < 21 天是「学习中」，≥ 21 天是「熟练」。

### 5. 卡片墙（浏览）

- 入口：左栏新增「简卡」（显示今日到期数）。
- 顶部：「今日复习 N 张」按钮；筛选（全部 / 分组 / 标签 / 关键字）；排序（最近添加 / 快到期 / 最不熟）。
- 网格：每张卡显示标题、要点（过长就截断，点开看全部）、来源笔记、熟练度色点、下次复习时间。
- 宽屏 3~4 列，窄屏 1 列；浅色 / 深色都适配，颜色只用设计 token。
- 点卡片：展开看完整内容；「打开原笔记」跳到笔记里这张卡的位置。

### 6. 今日复习（记忆）

- 入口：卡片墙顶部按钮、首页「今日复习」、快捷键 `Ctrl+Shift+R`；右栏显示「这篇有 5 张简卡，2 张到期」，可以只复习这篇。
- 范围：跟随卡片墙当前的筛选（选了「线性代数」分组，就只复习这一组）。
- 顺序：先到期的旧卡，再新卡；新卡每天最多 20 张（可调），旧卡每天最多 200 张。
- 一张卡：只显示标题 → 空格 / 点击翻面看要点 → 按 1~4 打分 → 下一张。
- `Ctrl+Z` 撤回上一次打分（日志里追加撤销记录，不删历史）。
- 结束页：本次复习张数、记住率、明天预计到期数。

### 7. AI 提炼简卡（第二阶段）

- 右栏 AI 加「提炼简卡」：AI 读当前笔记，返回几张候选简卡（标题 + 要点）。
- 你逐张勾选、可以改文字，确认后写到笔记末尾的 `## 简卡` 一节（没有就新建）。
- 写入走现有的 AI 插入通道，能 `Ctrl+Z` 撤回（约束 6）。

## 八、验证

- 单测 `cards.test.ts`：两种写法；普通引用 / 代码块 / `std::vector` 不误认；改要点 id 不变；改标题按相似度继承；改文件名不变；同名卡片加序号。

- 单测 `review.test.ts`：日志重算与逐次打分一致；撤回；每日新卡上限；删索引后从日志恢复。
- 接口测试：卡片墙筛选排序、队列、打分、撤回、范围筛选。
- 基准：5000 张卡、5 万条日志，启动重算 < 300ms（进 init.sh）。
- E2E：笔记里写两种简卡 → 卡片墙出现并能按分组筛选 → 今日复习翻面、打分 → 到期数减少 → 重启后进度还在。

## 十一、实现时的补充（2026-11-15）

- **算法版本**：移植的是开源参考实现 py-fsrs 6.x（FSRS-6，21 个默认参数）。设置：学习步只有 10 分钟一步、重学步 10 分钟一步、不加随机抖动（日志重放可复现）。所以新卡四档是「10 分钟 / 15 分钟 / 2 天 / 8 天」，和第六节举例的数字略有不同。
- **核对方式**：本来打算在同样设置下运行参考实现、对数值。运行下载的第三方代码被环境的安全策略拦下，于是改为逐行对照源码移植；单测核对公开默认参数给出的初始稳定性 / 难度，以及间隔单调、忘了降稳定性、到期时记住率约 90% 等性质。
- **复习状态不进 SQLite**：原计划的 `review_state` 表没做——启动时从日志重放、放在内存里（5000 张卡 + 5 万条记录约 70ms，基准 `pnpm bench:review` 进了 init.sh）。SQLite 只有可重建的 `cards` 表。
- **接口**：没有单独的 `/api/review/stats`；统计放在 `/api/cards`、`/api/review/queue`、`/api/review/summary` 的返回里（含「明天到期」）。
- **队列顺序**：到期的旧卡 → 新卡 → 今天晚些才到期的（刚答「忘了」的卡），免得翻过马上又出现。
- **预览**：简卡显示成卡片，但还没有显示熟练度小标签（要把复习状态传进预览，留待以后）；列表项里的 `- 概念 :: 解释` 能被识别成简卡，预览里按普通列表显示。
- **右栏**：只在保存后正文里「简卡相关的行」变了时才重新查这篇的卡片数，保持「只改正文时一次保存只发 1 个请求」。
- **备份**：日志在云端是 `_review/log.jsonl`（latest / 每日快照 / 月度归档都有），不出现在「从快照恢复笔记」的列表里；换电脑时手动拷回 `data/review/log.jsonl`。
- **摘要**：列表摘要去掉 `[!card]` 这类 callout 标记。
