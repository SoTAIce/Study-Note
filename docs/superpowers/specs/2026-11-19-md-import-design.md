# 拖入 .md 文件导入成笔记 设计方案

日期：2026-11-19
状态：**已批准（2026-11-20）**，已完成（见第九节实现记录）
对应条目：import-001（`feature_list.json`）

## 一、要解决的问题

手头有别处写好的 Markdown 文件（Obsidian、Typora、外部 AI 导出的回答、以前的笔记），想放进来。

现在只能新建一篇再复制粘贴：标题要重打，文件头里的标签丢了。往正文框里拖 `.md` 文件，只会提示「只支持 PNG、JPG、GIF、WebP 图片」。

## 二、已确定的需求（2026-11-19 问答）

| 问题 | 结论 |
|---|---|
| 拖到哪里 | 窗口任意处都能拖进来新建；拖到某个项目（左栏的分组 / 子项目行、正在连读的项目）上就导入到这个项目 |
| 放进哪个分组 | 每次弹框确认；拖到项目上时，框里预先选好那个项目 |
| 文件自带的文件头 | 保留原有的键（包括应用不认识的），缺的由应用补上 |
| 一次拖多个 | 一次只导一个 |

## 三、用户看到什么

1. **拖动时：**
   - 文件拖进窗口，整个窗口出现半透明遮罩：「松开导入为新笔记」。
   - 移到左栏某个分组 / 子项目行上，这一行高亮，遮罩改成「松开导入到『冒烟测试/looprun』」。
   - 在连读页里，遮罩写「导入到『这个项目』」。
2. **松开后弹出「导入笔记」小框：**
   - 文件名、识别出的**标题**（可以改）、正文前几行预览；
   - 文件头里保留下来的键（如 `tags: 读书, 复习`、`aliases`），只读列出；
   - **放进哪个分组**：下拉框。预选规则：
     - 拖到项目上 → 那个项目；
     - 否则 → 左栏当前选中的分组 / 正在连读的项目；
     - 都没有 → 「不分组」。
   - 提示：「文件里引用的本地图片不会一起导入」（正文里有 `![](相对路径)` 时才显示）；
   - 「导入」「取消」。
3. **导入后：**
   - 打开这篇笔记的编辑页；
   - 提示「已导入《标题》到『分组』」；
   - 左栏计数、列表跟着更新。
4. **拖了多个文件：** 只取第一个 `.md`，框里写「一次只导一个，这次导入《a.md》」。
5. **拖的不是 .md：**
   - 图片照旧（拖到正文框里插图）；
   - 其它文件提示「只能导入 .md 文件」。

## 四、标题和文件头

**标题**，依次取：

1. 文件头的 `title:`；
2. 正文第一个 `# 标题`；
3. 文件名去掉扩展名。

**文件头：**

| 键 | 处理 |
|---|---|
| 应用不认识的键（`aliases`、`cssclass`、自定义键）、块状 `tags` | **原样保留**，顺序不变（复用 data-001 的 `rewriteFrontmatter`） |
| `title` | 用框里确认的标题 |
| `tags` | 保留 |
| `group` | 用框里选的分组（「不分组」时去掉这一行） |
| `created` | 合法就保留，否则用导入时间 |
| `updated` | 导入时间 |
| `id` | 没有，或者和库里已有笔记重复时，换一个新的 |
| `type` | 合法（note / idea / …）就保留，否则 `note` |
| `template` | 保留（模板不存在时编辑页照常显示「模板『X』已不存在」） |

**正文**一个字不改，包括开头的 `# 标题`。

**文件名**按应用的规则从标题生成（`日期-标题.md`）。重名时自动加后缀，不覆盖已有文件。

## 五、接口

| 接口 | 说明 |
|---|---|
| `POST /api/notes/import` | `{ fileName, content, group, title }` → 和新建笔记一样返回新笔记 |

服务端：

- 校验：
  - 内容是字符串，不超过 2MB；
  - 去掉 BOM，统一换行；
  - 分组名按现有规则校验。
- 解析文件头：坏的文件头（没闭合的 `---`）当作没有文件头，整段算正文。
- 经 `store.ts` 原子写入，写完进索引。
- 推送通道照常通知其它标签页。

前端读文件用 `File.text()`。不是 UTF-8 的（解码出替换字符）提示「文件不是 UTF-8 编码」，不导入。

## 六、约束

- Markdown 文件仍是唯一真源，导入只是新建一个 `.md`；写入走 `store.ts`。
- 不新增依赖；颜色只用 token，浅色和深色都检查。
- 只监听 127.0.0.1、Host / Origin 闸门不变：文件内容由页面读出来再发给本机服务，服务端不去读任意路径。

## 七、不在这次范围

- 一次导入多个、导入整个文件夹。
- 文件里引用的本地图片一起导入：浏览器拿不到相对路径对应的文件。以后可以做成「把图片和 .md 一起拖进来」。
- `.txt`、`.docx` 等其它格式。

## 八、测试

- **单元测试**：
  - 标题来源的三种情况；
  - 文件头合并：未知键和块状 tags 原样保留、`group` 覆盖或去掉、`id` 冲突换新、`created` 不合法时补上；
  - 坏文件头当正文；
  - BOM、CRLF。
- **接口测试**：
  - 正常导入：文件在、索引里有、文件头符合上表；
  - id 冲突；
  - 超过 2MB 返回 413；
  - 分组名非法返回 400；
  - 重名不覆盖。
- **E2E**：
  - 拖 `.md` 到窗口空白处：遮罩 → 框里标题和预览对 → 选分组 → 导入 → 打开编辑页；
  - 拖到左栏子项目行：框里预选这个项目；
  - 拖两个文件只导第一个，框里有说明；
  - 拖 `.txt`：提示只能导入 `.md`；
  - 浅色和深色各截一张图。

## 九、实现记录（2026-11-20 完成）

按方案做完，以下几处是方案没写细、实现时定下的：

- **拖到正文框上**：正文框只接图片（插图，照旧）；拖的是 `.md` 等其它文件时不拦，交给窗口上的导入。以前拖非图片文件到正文框会提示「只支持 PNG、JPG…」，现在 `.md` 走导入、别的提示「只能导入 .md 文件」。粘贴图片的规则不变。
- **拖到窗口别处不会再把页面换掉**：以前把文件拖到正文框以外的地方松手，浏览器会直接打开这个文件、离开应用。现在窗口上统一拦下。
- **`.markdown` 扩展名**也算。
- **标题来源**：前端按「文件头 title → 第一个 # 标题 → 文件名（去掉开头的日期，- 和 _ 当空格）」预填进框里，人确认后作为 `title` 发给服务端；服务端用 `parseNote` 同一套规则兜底。
- **id**：文件头的 id 合法（不含空白和控制字符、不超过 64 个字）且库里没有才留着，否则换新的。
- **乱码**：前端读出来有替换字符（不是 UTF-8）时不弹框，直接提示；服务端也挡一道。
- **标题**：最长 200 个字，不能有控制字符。
- **分组**：选了库里还没有的分组名（比如拖到连读页、项目刚改名）时，和新建笔记一样登记进 `groups.json`。

接口：`POST /api/notes/import { fileName, content, title, group }` → 201，和新建笔记一样返回新笔记。错误：400（不是 .md、没内容、乱码、标题不对、分组名非法）、413（超过 2MB）。

E2E 的诊断改进：页面报错前面带上是哪一步报的，偶发的报错能直接定位。

验证：见 `feature_list.json` import-001 的 evidence 与 `docs/测试文档-2026-11.md` 第十六节。
