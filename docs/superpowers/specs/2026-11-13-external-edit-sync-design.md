# 外部编辑后界面自动同步（sync-001）设计

日期：2026-11-13 · 状态：待批准

## 一、现状与问题

- 后端已经在监听文件：`Indexer.watch()` 用 `fs.watch(notesRoot, { recursive: true })`，防抖 250ms 后重建这篇的索引。**索引是新的，但浏览器不知道。**
- 前端只在自己操作后才刷新列表（`loadList` + `refreshSidebar`），没有任何「服务端有变化」的通知，也不监听窗口重新获得焦点。
- 结果：
  1. 在 VS Code / Obsidian 里改了标题或标签，左栏、标签云、最近更新都不变，直到手动刷新页面。
  2. 正打开的那篇在外部被改了，编辑器里还是旧内容；没有未保存修改时用户看到的是过期内容。
  3. 有未保存修改时，要等下一次自动保存撞出 409 才出冲突提示。这时用户可能已经在旧内容上又写了一大段。
  4. 外部删除或移动了正打开的那篇，界面毫无反应。
  5. 两个浏览器标签页同时开着时，彼此的修改也互相看不到（和外部编辑是同一个问题）。

## 二、目标

1. **几秒内可见**：外部改动后 2 秒内，左栏列表、分组计数、标签、最近更新、已打开的标签页标题都更新。
2. **干净就自动重载**：正打开的那篇没有未保存修改时，自动载入磁盘版本，光标和滚动位置尽量保持，并给一个轻提示。
3. **有修改就先提示**：有未保存修改时，**立刻**显示现有的冲突提示条（保留我的 / 载入磁盘版本），并暂停自动保存。不等撞 409，也绝不静默覆盖任何一方。
4. **删除 / 移动有交代**：外部移动（id 不变）时编辑器继续可用；外部删除时告诉用户，保留编辑器里的内容，让用户决定。

## 三、非目标

- 不做多人协同或字符级合并（不做 CRDT / OT）。冲突仍由人选择。
- 不同步 `.history`、`.trash`、配置文件的变化。
- 不改变「Markdown 文件是唯一真源」和现有的 baseHash 冲突检测；这次只是让冲突**更早被看见**。
- 不引入新依赖（不用 chokidar、socket.io）。

## 四、反目标（出现这些就算失败）

- 用户正在打字时，编辑器内容被外部版本替换掉。
- 自己的保存被当成外部修改，导致编辑器自己重载自己、光标乱跳或误报冲突。
- 批量外部操作（git pull、同步盘一次落 500 个文件）让浏览器连发几百次请求或卡住。
- 事件通道断了之后界面永远停在旧状态。

## 五、方案

### 1. 推送通道：SSE `GET /api/events`

- 用浏览器原生 `EventSource`，复用现有的 `server/sse.ts`（已带心跳和背压）。不用 WebSocket，因为只需要服务端到浏览器的单向推送，SSE 的断线自动重连是现成的。
- 这是 GET 请求，照常走 `server/app.ts` 的 Host 闸门；只推送「哪篇变了」，不推正文，前端需要内容时再走现有的 `GET /api/notes/:id`。

### 2. 事件从哪里来：索引层统一发出

在 `Indexer` 上加一个很小的变更通知（`node:events` 的 `EventEmitter`，或一个回调数组）：

- `indexFile(relPath)` 完成后发 `{ kind: "changed", id, path, hash }`。
- `removeFile(relPath)` 完成后发 `{ kind: "removed", id, path }`。
- `reindexAll()` 完成后发一次 `{ kind: "resync" }`，不逐篇发。

**为什么在索引层而不是只在 watcher 里发**：应用自己的写入（保存、移动分组、AI 计划执行、备份恢复）都会调用 `indexFile`，watcher 会忽略这些自写事件。从索引层发，就能同时覆盖「外部编辑器」和「另一个浏览器标签页」两种情况，代码路径也只有一条。自己标签页的保存用 hash 比对过滤掉（见下文第 4 节）。

### 3. 合并与限流（服务端）

- 新建 `server/events.ts`（纯逻辑，便于测试）：每个连接一个缓冲区，**300ms 内的变化合并成一条消息**：`event: notes` / `data: { changes: [...] }`。同一路径只保留最后一次变化。
- 一个窗口里超过 **100 条**变化时，只发 `{ resync: true }`，让前端整体刷新一次，不再逐条处理。
- 连上时先发一条 `event: hello`，带服务端启动标识。前端重连后如果发现标识变了（服务重启过），按 resync 处理。

### 4. 前端处理（新建 `web/src/lib/live.ts` + 在 `App.tsx` 接线）

**连接管理**（`live.ts`，不依赖 React，可单测）：
- 打开 `EventSource("/api/events")`。断线由浏览器自动重连；**重连成功后统一做一次 resync**，补上断线期间漏掉的变化。
- 页面隐藏超过 30 秒后再回来（`visibilitychange`）也做一次 resync。这同时兜住 `fs.watch` 在网络盘、部分同步盘上漏事件的情况。

**收到变化后**：

| 情况 | 处理 |
|---|---|
| 任何变化 | 防抖 300ms 后刷新一次左栏：`loadList(filter)` + `refreshSidebar()`；已打开标签页的标题跟着更新 |
| 变化涉及**当前打开的这篇**（按 id 匹配） | 等进行中的保存结束 → `GET /api/notes/:id` → 比较磁盘 hash 和 `hashRef` |
| └ hash 相同 | 是自己（或刚好内容一致）的写入，什么都不做 |
| └ hash 不同，且没有未保存修改 | 自动载入磁盘版本（复用 `resolveReload`），尽量保持光标和滚动位置；提示「已载入外部修改」 |
| └ hash 不同，且有未保存修改 | 立刻显示现有冲突提示条，复用 `ConflictInfo`（`currentHash` 取磁盘 hash），暂停自动保存。按钮仍是「保留我的（覆盖磁盘）」和「载入磁盘版本」 |
| └ 返回 404（外部删除，或移出了笔记目录） | 编辑器顶部显示「这篇笔记已在外部被删除或移走」，暂停自动保存，保留编辑器里的内容；提供「另存为新笔记」和「关闭」两个按钮 |
| 外部移动或改名（id 不变） | 后端按 id 找文件，所以 `GET /api/notes/:id` 照常成功，只是 `relPath` 变了，更新 `current` 即可，无需打扰用户 |
| 正打开的笔记之外被删除，但它在打开的标签页里 | 标签页标记为失效；点击时走现有的「打不开」提示，不自动关闭 |

**为什么当前这篇总要「拉一次再比 hash」而不直接用事件里的 hash**：外部移动会先后产生「旧路径删除」和「新路径新增」两个事件，顺序不固定；自己的保存回来时 `hashRef` 也可能还没更新。拉一次、等保存结束再比，结果只取决于磁盘的最终状态，不受事件顺序影响。代价是每次外部改动多一次请求，量很小。

**「保持光标」的做法**：重载前记下 textarea 的 `selectionStart` / `selectionEnd` / `scrollTop`。新内容长度够就原样恢复，不够就夹到末尾。不做基于 diff 的光标映射（收益小，复杂度高）。

### 5. 边界情况

- **自己的保存回声**：保存成功后 `hashRef` 等于磁盘 hash，比对相同，不会触发任何动作。保存进行中收到的事件，会等这次保存结束后再比对。
- **用户已经在冲突状态**：再收到外部变化时，只更新冲突提示里的 `currentHash` 和时间，不重复弹提示。
- **编辑器正在新建页 / 首页**：只刷新左栏。
- **HTTP/1.1 每个站点 6 条连接的上限**：每个标签页常驻 1 条 SSE。开 6 个以上标签页，再加上 AI 对话的流式请求，可能排队。本地个人使用可以接受，记为已知限制；以后需要时可以用 `BroadcastChannel` 让多个标签页共用一条连接（不在本次范围）。
- **服务关闭**：`main.ts` 的 `shutdown` 里先结束所有 SSE 连接，否则 `server.close()` 会等这些长连接。

## 六、改动清单

后端：
- `server/events.ts`（新）：变更合并缓冲、超量转 resync、消息格式。纯函数加一个小类，可注入时钟。
- `server/indexer.ts`：`onChange(listener)`，在 `indexFile` / `removeFile` / `reindexAll` 之后发事件。watcher 逻辑不变。
- `server/api.ts`：`GET /api/events`，用 `sseStart`，连接断开时取消订阅。
- `server/main.ts`：关闭时结束 SSE 连接。

前端：
- `web/src/lib/live.ts`（新）：`EventSource` 封装、重连后 resync、可见性兜底、变化合并（可单测）。
- `web/src/api.ts`：事件类型。
- `web/src/App.tsx`：订阅；左栏防抖刷新；当前笔记的比对、重载、冲突、删除处理；重载时保持光标。
- `web/src/components/EditorPane.tsx`：「已在外部删除或移走」提示条（复用 `.conflict` 样式）。
- 样式只用现有 token。

## 七、测试

- `server/tests/events.test.ts`：300ms 内合并；同一路径只保留最后一次；超过 100 条转 resync；断开后不再推送。
- `server/tests/indexer.test.ts`：`indexFile`、`removeFile`、`reindexAll` 都发出正确事件；**真实 `fs.watch`**：在临时目录外部写文件后，订阅者在 2 秒内收到 `changed`。
- `server/tests/api.test.ts`：`GET /api/events` 返回 `text/event-stream`，先收到 `hello`；通过 API 保存一篇后收到包含该 id 的 `notes` 事件；非本机 Host 返回 403。
- `web/src/lib/live.test.ts`：重连触发 resync；页面可见性兜底的时间判断；合并逻辑。
- `scripts/e2e.mjs` 新增 3 步：
  1. 外部改另一篇笔记的标题 → 左栏 2 秒内显示新标题。
  2. 打开一篇、不改动 → 外部改正文 → 编辑器自动显示新内容，出现「已载入外部修改」。
  3. 打开一篇、输入但不等保存 → 外部改正文 → 出现冲突提示条；点「载入磁盘版本」后内容是外部版本，磁盘文件没被浏览器覆盖。
- 变异检查：注释掉前端的订阅，E2E 第 1 步应失败。
